# Lessons

## 2026-10-12 — Specification review

- Keep priority separate from release scope and encode dependencies explicitly; phase numbers alone are insufficient.
- Check worked examples with exact arithmetic and define units, signs, rounding, and reservation lifecycle before implementing money handling.
- Validate that short-duration packs can deliver their advertised allowance under every applicable cap.
- A stub verifies the evaluation harness; only authorized real-model evidence can establish model quality.
- Validate patch context before applying it. Inspect changed regions, references, and semantic consistency after a successful edit.

## 2026-10-12 — Bootstrap verification on Windows

- Use NUL-separated binary input/output for Git path-list probes from Python; Windows text-mode pipes can translate LF to CRLF and turn the carriage return into part of a tested filename.
- Verify a scanner with a temporary synthetic finding as well as a clean repository; check failure status, redaction, and cleanup instead of treating configuration-file existence as proof.

## 2026-10-12 — Pricing research record check

- Count the title within HANDOFF.md's five-line limit; keep the next step and its missing inputs on one line. The final record check caught and corrected a six-line handoff.

## 2026-10-13 — Dependency research and guidance checks

- Summarize advisory IDs/counts and only relevant ranges in tool output; large API payloads can truncate and invalidate JSON evidence. Do not treat an incomplete patch label, a rate-limited feed or zero repository records as a clean dependency audit.
- Follow the memory-file paths in AGENTS.md rather than assuming they are at the repository root; check every current next-step pointer, including guide footers, after updating a milestone.

## 2026-10-13 — Hosting decision research

- Check price date, region, availability, tax/IP/backup scope and renewal separately. A dated price schedule, a future-labelled range or a "from" price is not a currently purchasable all-in quote; traffic-alert emails and per-instance price caps do not prove bounded account spending.
- Source-reference validators must allow digits in valid labels such as R2; verify the checker before treating a failed source count as a missing research entry.

## 2026-10-13 — Evaluation provenance review

- Generate canned-run provenance inside the harness; imported JSON cannot grant itself stub identity, observed costs or owner approval. Independent review reproduced both false-label paths and regression tests now cover their fixes.
- Syntax-only checks and simulated review labels validate grader mechanics; they never prove real coding behavior, Bangla fluency, model eligibility or phase readiness. Keep functional/real evidence unknown until observed under approved scope.

## 2026-10-13 — Gate-report record update

- Read Markdown with explicit UTF-8 in Windows PowerShell before using output as patch context; legacy default decoding can corrupt punctuation and make an otherwise valid append fail. Re-read the actual line rather than reusing the corrupted output.

## 2026-10-13 — Local prototype tooling

- Use npm.cmd or the reviewed Node/npm CLI wrapper under Windows script restrictions; do not loosen the user's global execution policy.
- Override inherited Node TLS-disable settings for repository-local dependency operations, use the system CA store and a fresh verified cache, and compare every locked package integrity to HTTPS official metadata before execution. Explicitly include dev dependencies when the host omits them by default.
- Scope browser globals to browser-test files in lint configuration; Node server scripts should not inherit permissive browser globals.

## 2026-10-13 — Local Phase 1 verification

- Equal timestamps do not order chat turns. Random UUID sorting can place an assistant first and reverse gateway context; use a durable insertion sequence and deterministic tied-time/reversed-ID regressions.
- Track a requested cancellation separately from a late terminal stream error so localized stopped status survives the race. Verify both language flows in the browser.
- Hold UI readiness through asynchronous session/history/account restoration. A reload test should delay the history response explicitly and check that input/new-chat controls stay disabled; a fast response can hide an initialization race.
- A generic SQL flag is not a privileged retention boundary. Preserve append-only audit/usage records when an embedded connection can assume every role; disclose deferred expiry and enforce admission caps with reserved logout/deletion/settlement capacity.
- Include dev dependencies explicitly in npm advisory audits as well as installation; inherited npm omission settings can otherwise skip the reviewed development graph.
- Use exact, fresh whole-line patch context. A sentence inside a paragraph cannot be matched as a separate full line; failed patches are atomic and should be corrected before proceeding.
- Keep local completion, unavailable independent reviews, configured-but-unrun CI and original real-account/hosted acceptance separate. Synthetic tests cannot close missing external evidence.

## 2026-10-13 — Pre-host integration review

- Bind the actual system/prompt bytes to the approved suite hash; a separately supplied digest does not authorize replacement payloads. Check account capacity for the first request as well as pacing later calls.
- Recheck authorization expiry after awaited storage work and immediately before dispatch. Clamp in-flight transport to remaining validity and keep an already reserved attempt spent when validity is crossed.
- Make deletion idempotent inside the locked transaction. Hashing an already hashed tombstone on a duplicate request can permit re-registration and quota reset; check status before mutating it and repeat admission after reading the HTTP body.
- Version privacy drafts when adding real identity or evaluation processing; describe exact local storage/retention and keep legal clearance unknown. Initial synthetic fixtures must never appear as actual provider/account evidence.

## 2026-10-13 — Phase 2 registry review

- Validate operation options separately from record fields; private seed observations and version actions must not be caller overrides. Canonicalize object keys for semantic idempotency and return validation failures through the service's consistent asynchronous contract.
- Row-count caps alone do not bound JSON storage. Whitelist imported observations, bound approved values and serialized records, and add a DB byte backstop in a new migration rather than changing an already-applied checksum.
- Record DB-verified staff role/target type in audit inserts and actor/time in version history; default user attribution obscures privileged changes. Preserve append-only development evidence after fixing future inserts.

## 2026-10-13 — Step2.2 ledger verification

- Read accounting BIGINT fields as SQL text before PGlite's default number parser; converting a rounded JS number to BigInt cannot recover lost digits. Test values above the safe-integer boundary through DB reservations and history.
- Show unknown dispatched usage as pending reconciliation. An immutable estimated row and a corrected latest view are distinct from an unresolved attempt; never label the latter resolved.
- Zero CU can still fund a verified zero-cost route. Derive route-specific funding refusals from the requested bound; account summaries must not imply every route needs positive money.
- A local registry can contain more than one eligible synthetic fixture. Explicitly select the canned chat model for the ledger preview and verify the actual launcher/owned views; preserve the original default's one-model guard.

## 2026-10-13 — Step 2.3 Governor verification

- A pre-marker clock check can become stale during later awaited counter/journal writes. Recheck every captured quota window and reservation expiry after all awaited application writes, then reject and roll back the complete dispatch if a boundary passed. Inject clock changes at allocations, journal, storage and guard writes to test this.
- Idempotent maintenance replay must report no newly changed item. Concurrent workers can observe the same pending row; distinguish a cached estimate from the one transaction that actually appends it.
- A conservative daily request-to-token conversion can be tighter than the token counter. Assert the minimum applicable budget rather than assuming a token-only remainder; retain request limits as separate atomic admission constraints.
- Verify captured history hashes using their original byte or character count convention. A byte prefix cannot be sliced as a JS string; milestone audits must include5a/5b rather than assuming every phase is numeric.

## 2026-10-13 — Step 2.4 Router verification

- Keep the prepared policy version and policy data together. Replanning against a newly active version while recording the old version gives misleading evidence and can weaken a request's constraints.
- An async generator can yield an attempt event before entering its underlying transport. Enter the iterator before exposing a started attempt, and attach rejection handling immediately. Prove zero use only on the private path before gateway function entry; an abort after accounting commit still needs a joint refund of every captured request/token/fund bound.
- User stops are not provider failures. Successful requests must not erase other failures inside the configured breaker window, and in-flight success must not close an unexpired breaker.
- Deleting private chat must remove attempt content without discarding pending accounting obligations. Keep a bounded minimal reconciliation record with captured old counters and no prompt/output; verify one estimate/correction after deletion.
- Derive daily job keys and job timestamps under the same transaction guard. Midnight can cross during an await; reject/roll back a changed local day and retry with the new key, including cached replay. A policy job never grants funds.
- Scope browser attempt assertions to assistant replies; empty user-message containers are not an additional attempt. Verify the real saved model and fallback banner rather than counting a generic selector.
- Multiple PGlite/WASM suites can exhaust this machine's memory even when application checks pass. Preserve previews, stop the failing coordinator, run suites serially with verified exposed-GC/one-WASM-task settings and record the failed run separately from final passes.

## 2026-10-13 — Step 2.5 execution interruption

- An automatic approval-review usage failure is an execution blocker, not a finding that an action is unsafe. Preserve the exact failed action/reason, use only an allowed lower-permission alternative, and never bypass review. Here the lower-permission sandbox also failed before execution.
- Save authored code/test contracts and pending checks when tool or reviewer usage is exhausted. Keep the step IN PROGRESS; preliminary builder reports and earlier-version passing suites cannot close new authentication/quota/security behavior.

## 2026-10-14 — Step2.5 verification

- Freeze synthetic unit-test time when asserting a burst within one minute. A wall-clock boundary legitimately resets the allowance; inject time deliberately in separate reset/TTL tests.
- A final guard must run after outer transaction writes as well as nested service writes. Register only synchronous completion checks and invoke them after the last awaited write.
- Enforce trust token limits on paid routes too. Retain exact captured day/used/reserved counters through uncertainty, deleted chat, estimates, late corrections and pretransport zero-use restoration.
- Suspension expiry must precede active-only session lookup for an otherwise valid owned session. Current ban prevents new work but must not prevent trusted in-flight accounting closure.
- Keep the HMAC key stable with stored pseudonyms; bind the database to a fingerprint before callback entry and prove a wrong key makes no writes on actual file reopen.
- UTF-8 BOM can break SQL/JSON parsers. JavaScript replacement strings interpret special sequences such as dollar-apostrophe; use literal callbacks or exact checked content for SQL repairs. Preserve table definitions and rerun migration/durability checks.
- Assert intentional cancellation errors before checking refunds, and allow rendered whitespace in text assertions. These corrections do not replace the resulting accounting/browser assertions.
